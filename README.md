# OJS demo kit — демо-стенд научного журнала

Набор для превращения чистой установки **Open Journal Systems 3.5** в демонстрационный стенд для клиентов:

| Задача | Что сделано | Где лежит |
|---|---|---|
| 1. Академический дизайн | Тема «Академический журнал» (дочерняя к стандартной): шрифты Source Serif 4 + Inter (свои, без Google), шапка с ISSN и переключателем языка, главная с блоком-приветствием, статистикой и текущим выпуском, карточки архива, оформление статьи, информативный подвал, адаптив под телефон | `plugins/themes/academicJournal` |
| 2. Тестовые данные | Двуязычный (ru/en) журнал «Вестник междисциплинарных исследований»: 3 выпуска с обложками, 14 статей с PDF-гранками, 4 материала в работе (в т.ч. на рецензии у демо-рецензента), редакция из 10 человек, объявления, статистика просмотров за 18 месяцев | `seed/` |
| 3. Демо-режим | Плагин «Демо-режим»: демо-администратор видит все разделы и формы, но **ничего не сохраняется** (запись блокируется до обработки запроса); вход в один клик под ролями «Администратор / Редактор / Рецензент / Автор»; плашка «Демо-режим». Плюс автоматический **сброс данных** по cron из эталонного снимка | `plugins/generic/demoMode`, `scripts/demo-*.sh` |
| 4. Безопасность | `.htaccess` (исполняется только `index.php`, закрыт доступ к коду/конфигу/кэшу, запрет PHP в `public/`, лёгкий WAF, заголовки безопасности), проверка и правка `config.inc.php`, права файлов, ALTCHA-капча, аудит: целостность ядра против официального релиза, поиск веб-шеллов, проверка того, что открыто снаружи | `security/`, `scripts/harden.sh`, `scripts/security-audit.sh` |
| + | Дополнение русского перевода OJS 3.5 (564 строки интерфейса, которых нет в официальной локализации и которые показывались как `##ключ##`) | `plugins/generic/ruLocaleCompletion` |

Всё проверено на чистой OJS **3.5.0-1** (PHP 8.3, MariaDB 10.11, Apache 2.4): установка, наполнение, все страницы сайта и панели управления, блокировка записи, сброс, аудит.

## Быстрый старт (сервер sweb, по SSH)

> На **ваших** путях: сайт лежит в `~/ojsdemo_new`. На sweb файлы сайта обычно находятся в подкаталоге
> `public_html` — скрипты находят его сами (можно указать и полный путь к каталогу с `config.inc.php`).

```bash
ssh sweb
cd ~
git clone https://github.com/vlad-m/rads-ojsdemo.git
cd rads-ojsdemo

# 0. Посмотреть, что за сервер и какая версия OJS (пароли не выводятся)
scripts/inspect.sh ~/ojsdemo_new

# 1. Резервная копия текущего состояния (на всякий случай)
scripts/demo-snapshot.sh ~/ojsdemo_new ~/ojs-backup-before-demo

# 2. Всё сразу: плагины, тема, наполнение, демо-режим, защита, эталонный снимок
scripts/deploy.sh ~/ojsdemo_new --journal=nj --seed --demo --harden --snapshot

# 3. Проверка безопасности (подставьте адрес сайта)
scripts/security-audit.sh ~/ojsdemo_new --url https://ВАШ-ДОМЕН
```

Каждую команду — отдельной строкой.

`--journal=nj` — наполнить существующий журнал `nj`: его настройки (название, описание, ISSN, тема и т.д.)
заменяются демонстрационными, добавляются выпуски, статьи, материалы в работе и объявления; уже существующие
материалы журнала не удаляются, а повторный запуск ничего не дублирует. Без `--journal` создаётся новый журнал `jir`.

**PHP.** На sweb `/usr/bin/php` в SSH — старый PHP 5.2, а OJS 3.5 нужен PHP 8.2+. Скрипты сами ищут
`php8.x` (`/usr/local/bin/php8*` и др.). Если не нашли — укажите путь явно, версию берите ту же, что у сайта
в панели: `PHP=/usr/local/bin/php8.2 scripts/deploy.sh …` (список: `ls /usr/local/bin/ | grep php`).

### Cron (панель sweb → «Планировщик задач» или `crontab -e`)

```cron
# Сброс демо-данных каждые 3 часа
0 */3 * * * /bin/bash $HOME/rads-ojsdemo/scripts/demo-reset.sh $HOME/ojsdemo_new >> $HOME/ojs-demo-reset.log 2>&1
# Плановые задачи OJS (обязательно для 3.5)
* * * * * cd $HOME/ojsdemo_new && php lib/pkp/tools/scheduler.php run >> /dev/null 2>&1
```

## Демо-доступ

| Роль | Логин | Пароль |
|---|---|---|
| Администратор (админ сайта + управляющий журнала + главный редактор) | `demo` | `demo` |
| Редактор | `demo-editor` | `demo` |
| Рецензент (есть назначенный запрос на рецензию) | `demo-reviewer` | `demo` |
| Автор | `demo-author` | `demo` |

На странице входа эти роли показаны карточками — клик сразу авторизует.
Пароль меняется параметром `--password=...` у `deploy.sh` (и тогда его нужно указать заново при `--seed`).

### Как работает демо-режим

Включается **только** в `config.inc.php` (из интерфейса его отключить нельзя):

```ini
[demo]
enabled = On
superusers = "admin"          ; кому МОЖНО менять систему (ваша настоящая учётная запись)
password = "demo"             ; подсказка на странице входа
accounts = "demo,demo-editor,demo-reviewer,demo-author"
reset_hours = 3               ; текст на плашке «данные восстанавливаются каждые N ч»
```

- Для всех, кроме `superusers`, запросы `POST/PUT/PATCH/DELETE` отклоняются до того, как попадут в OJS:
  в формах появляется сообщение «Это демонстрационная версия: изменения не сохраняются…».
  Разрешены только вход/выход и поиск.
- Дополнительно закрыты GET-операции с побочными эффектами или утечкой данных:
  «Войти как пользователь», сброс пароля, сведения о системе / `phpinfo`, очистка кэшей, сброс сессий.
- «Войти как» не позволяет обойти защиту: если демо-пользователь каким-то образом окажется
  под учётной записью суперпользователя, права проверяются по исходному пользователю.
- Загрузка файлов (в т.ч. плагинов) невозможна — значит, через демо нельзя залить вредоносный код.
- Почта переводится в режим `log` (письма не отправляются), регистрация в журнале отключена,
  страницы помечены `noindex`.
- Даже если что-то изменится, cron каждые N часов возвращает базу, файлы и `public/` к эталонному снимку.

### Как обновить демо-контент

1. Войдите своей учётной записью из `superusers` — для вас изменения сохраняются (плашка становится красной).
2. Отредактируйте что нужно.
3. Сохраните новый эталон: `scripts/demo-snapshot.sh ~/ojsdemo_new`.

Полностью пересоздать журнал из `seed/content/journal.json`:
`scripts/deploy.sh ~/ojsdemo_new --seed --force --snapshot`.

## Безопасность — что делает `harden.sh`

Без `--apply` скрипт только **показывает** проблемы. С `--apply` (так его вызывает `deploy.sh --harden`):

- **`.htaccess` в корне** — исполняется только `index.php`; закрыты `config.inc.php`, `cache/`, `classes/`, `lib/pkp/classes`,
  шаблоны `.tpl`, `.po`, `composer.*`, дампы `*.sql`, архивы, бэкапы, dot-файлы и `.git`; блокируются обход каталогов,
  `php://`-обёртки, `UNION SELECT`, `<script>` в параметрах и известные сканеры; заголовки
  `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS (на HTTPS); убирается `X-Powered-By`.
- **`public/.htaccess`** — в каталоге загрузок PHP не исполняется вообще; SVG/HTML отдаются в «песочнице» (CSP), чтобы через
  загруженную картинку нельзя было выполнить скрипт.
- **`cache/.htaccess`** — полный запрет доступа.
- **`config.inc.php`** (с резервной копией `config.inc.php.bak-…`): `allowed_hosts` (защита от подмены Host),
  `force_ssl` при HTTPS, `session_check_ip`, случайный `api_key_secret`, выключены вывод ошибок и трассировки,
  `show_upgrade_warning`, `enable_beacon`; включена встроенная капча **ALTCHA** (регистрация, восстановление пароля;
  на входе — только если демо-режим выключен).
- **Права**: `config.inc.php` → 640, снимается запись «для всех». Опционально `--lock-code` делает код OJS
  только для чтения (вредоносу сложнее что-то дописать; перед обновлением — `--unlock-code`).
- **`.user.ini`** — `display_errors=Off`, `allow_url_include=Off`, защищённые cookie сессии.
- Проверяет, что каталог загрузок `files_dir` **вне** веб-корня, и ищет забытые дампы/архивы/`phpinfo.php`.

### Аудит: `security-audit.sh`

```bash
scripts/security-audit.sh ~/ojsdemo_new --url https://ВАШ-ДОМЕН
```

- скачивает официальный архив той же версии OJS и сравнивает **каждый файл ядра** — любые изменения и «лишние»
  исполняемые файлы будут показаны (так находят внедрённый код);
- ищет PHP-файлы в `public/`, `cache/`, `files_dir`; сигнатуры веб-шеллов и обфускации (`eval(base64_decode(...))` и т.п.);
  `auto_prepend_file` в `.htaccess/.user.ini`; недавно изменённые PHP-файлы;
- снаружи проверяет, что конфиг, код, кэш и служебные файлы недоступны, и что есть заголовки безопасности.

Код возврата `1`, если есть находки, — удобно запускать по cron раз в сутки и получать письмо.

### Что нужно сделать вручную

1. **HTTPS**: включить бесплатный сертификат Let's Encrypt в панели sweb, затем в `config.inc.php`
   `base_url = "https://…"` и снова `scripts/harden.sh ~/ojsdemo_new --apply`.
2. **Пароль администратора** (того, что в `superusers`) — длинный и уникальный; демо-пароль у него быть не должен.
3. Если `harden.sh` пишет, что **`files_dir` внутри веб-корня**, — перенести каталог за пределы `ojsdemo_new`
   и поправить `[files] files_dir`.
4. Следить за обновлениями OJS 3.5.x (исправления безопасности): после обновления — `deploy.sh` (без `--seed`)
   и `demo-snapshot.sh`.
5. На sweb статические файлы (`.tpl`, `.xml`, `composer.json` …) отдаёт сам nginx, и `.htaccess` к ним
   не применяется — аудит покажет их как «reachable». Отключите в панели для сайта обработку статики nginx
   (или попросите поддержку запретить для сайта `*.tpl`, `*.xml`, `composer.*`, `/lib/pkp/`). PHP-файлы
   и конфиг при этом уже защищены.
6. Удалите из веб-каталога копии и бэкапы (аудит покажет их как «directory not in the release»).

## Структура репозитория

```
plugins/
  themes/academicJournal/        тема (PHP, LESS, шаблоны Smarty, шрифты, ru/en)
  generic/demoMode/              демо-режим (блокировка записи, плашка, вход в один клик)
  generic/ruLocaleCompletion/    недостающие русские строки интерфейса OJS 3.5
seed/
  seed.php                       наполнение (создаёт журнал, пользователей, импортирует выпуски через Native XML)
  content/journal.json           весь контент журнала (ru/en)
  assets/pdf, assets/covers      PDF статей и обложки выпусков
  generator/                     исходники контента и генератор PDF/обложек (Playwright)
security/
  htaccess/*.htaccess            правила Apache
  robots-noindex.txt             robots.txt для демо
scripts/
  inspect.sh                     сведения о сервере и установке
  deploy.sh                      установка набора (плагины, наполнение, демо-режим, защита, снимок)
  harden.sh                      проверка/применение мер защиты
  security-audit.sh              аудит целостности и вредоносного кода
  demo-snapshot.sh               сохранить эталонное состояние демо
  demo-reset.sh                  восстановить эталон (для cron)
```

### Настройки темы

«Настройки → Веб-сайт → Оформление → Тема»: основной и акцентный цвет, блок-приветствие, подзаголовок
на главной (ru/en), статистика журнала. Логотип, изображение на главной и текст подвала берутся из стандартных
настроек OJS. Если загрузить логотип, он заменит текстовый заголовок с круглой эмблемой.

## Ограничения и примечания

- Набор рассчитан на **OJS 3.5.x** (в 3.3/3.4 другие API плагинов). `deploy.sh` предупредит, если версия другая.
- Скрипты сброса/снимка поддерживают MySQL/MariaDB.
- Все люди, организации, статьи и e-mail (`@example.org`) — вымышленные; ISSN имеют корректные контрольные
  цифры, но не зарегистрированы.
- Переводы в `ruLocaleCompletion` сделаны для 3.5.0-1; на более новых версиях часть строк уже будет в ядре — это не мешает.
